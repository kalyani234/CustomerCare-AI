# CustomerCare AI – LLM Quality Engineering Framework

An AI-powered customer support chatbot with an automated Quality Engineering framework for evaluating Large Language Model (LLM) responses.

The project demonstrates how to build, test, evaluate and monitor the quality of an LLM-powered customer support application using Python, SentenceTransformers, Groq API, Pytest and Streamlit.

## 1. Project Overview

Traditional customer support systems often depend on predefined responses and keyword-based matching. Customers, however, express the same questions in different ways.

CustomerCare AI uses semantic search and an LLM to understand customer questions and generate relevant responses.

Alongside chatbot development, this project introduces an automated AI Quality Engineering framework to evaluate response quality, identify hallucinations and validate whether generated answers are supported by the available knowledge.

### Key Objectives

- Build an LLM-powered customer support chatbot.
- Implement semantic retrieval using SentenceTransformers.
- Generate contextual responses using the Groq LLM API.
- Automate AI response quality testing.
- Evaluate answer relevancy, faithfulness and hallucination.
- Generate structured quality reports.
- Visualise evaluation results through a Streamlit dashboard.

## 4. How the Application Works

### Step 1: Customer Query

The customer submits a question through the chatbot.

Example:

"How can I request a refund?"

### Step 2: Semantic Embedding Generation

SentenceTransformers converts the customer question and knowledge-base content into numerical vector representations called embeddings.

These embeddings represent semantic meaning rather than relying only on exact keyword matches.

### Step 3: Similarity Search

Cosine similarity compares the customer query embedding with knowledge-base embeddings.

The system identifies the most relevant information for the customer's question.

### Step 4: LLM Response Generation

The retrieved knowledge and customer question are passed to the Groq-powered LLM with the configured system instructions.

The LLM generates a customer-support response using the supplied context.

### Step 5: AI Quality Evaluation

The generated response is evaluated against defined quality criteria:

- Answer Relevancy
- Faithfulness
- Hallucination

### Step 6: Quality Reporting

Evaluation results are stored in a structured JSON report and displayed through a Streamlit dashboard.

## 5. AI Quality Engineering Framework

The project focuses on three important dimensions of LLM quality.

### Answer Relevancy

Measures whether the generated answer addresses the customer's actual question.

Example:

Customer question: "What is the refund policy?"

Expected behaviour: The chatbot should provide information about refunds rather than unrelated delivery information.

### Faithfulness

Evaluates whether the generated response is supported by the retrieved knowledge or reference context.

Example:

Knowledge: Refunds are available within 30 days.

Generated response: Refunds are available within 60 days.

Expected result: The response fails faithfulness evaluation.

### Hallucination

Identifies information generated by the LLM that is unsupported by the available reference information.

Example:

The chatbot invents a refund policy that does not exist in the knowledge base.

Expected result: Flag the unsupported information for investigation.

## 6. Automated Testing

Pytest is used to automate application and quality validation.

Example test scenarios:

| Test scenario | Expected result |
|---|---|
| Valid customer question | Relevant response generated |
| Unrelated question | No misleading answer |
| Missing customer input | Appropriate validation |
| Incorrect information in response | Quality evaluation identifies the issue |
| Unsupported response | Faithfulness evaluation flags it |
| Hallucinated information | Hallucination evaluation identifies it |
| Repeated customer question | Response quality remains acceptable |

## 8. Example Evaluation Scenario

**Customer question:**

"Can I get a refund within 30 days?"

**Reference context:**

"Customers can request a refund within 30 days, subject to the applicable refund policy."

**Generated response:**

"Yes, customers can request a refund within 30 days."

Expected evaluation:

| Evaluation | Expected outcome |
|---|---|
| Answer Relevancy | High |
| Faithfulness | High |
| Hallucination | Low |

Now consider an incorrect response:

"You can request a refund within 90 days."

This should trigger a quality issue because the generated answer contradicts the reference context.

## 10. Installation and Setup

### Prerequisites

- Python 3.10 or later
- Groq API key
- Git

### Clone the repository

```bash
git clone YOUR_GITHUB_REPOSITORY_URL
cd CustomerCare-AI
```

### Create a virtual environment

```bash
python -m venv venv
```

Activate it:

Windows:

```bash
venv\Scripts\activate
```

macOS/Linux:

```bash
source venv/bin/activate
```

### Install dependencies

```bash
pip install -r requirements.txt
```

### Configure environment variables

Create a `.env` file:

```env
GROQ_API_KEY=your_groq_api_key
```

Never commit your actual API key to GitHub.

## 11. Running the Application

## 12. Quality Engineering Approach

The project follows an AI-focused quality engineering approach:

1. Validate customer input.
2. Verify semantic retrieval.
3. Validate generated responses.
4. Evaluate answer relevancy.
5. Evaluate faithfulness against reference context.
6. Identify hallucinations and unsupported claims.
7. Automate regression tests.
8. Generate quality reports.
9. Review results using the dashboard.
